# 第七轮：赛事内历史的来源去重核查

核查日期：2026-11-27。核查者为 features agent，赛事内状态模块由协调 agent 实现，来源去重补丁由 features agent 完成。此核查发生在赛事内状态模型评分前，由“球员在早轮输球后仍参加同届后轮”的结构性矛盾触发，没有根据预测错误挑选样本。它不修改已发布目标、标签或既有模型产物。新模块直接读取原始年度文件，最初绕过了既有库存的来源清洗，因此重新遇到了早已排除的记录；这不是原目标数据新发现了需要删除的样本。

官方 PDF 的 SHA-256：

`fd743799b7b7268ad4e02d3fbe044a0b23be39a0c4e6e8d4d09fabff69ded1b5`

可复查命令（使用临时文件，未将完整第三方 PDF 复制到仓库）：

官方签表明确显示：

- Tommy Robredo 为 2 号种子，位于签表第 32 位；第 31 位为 BYE，因此他首轮轮空，没有对 Paire 的 R32 比赛。
- Benoit Paire 位于第 4 位，首轮对第 3 位 Markus Eriksson，比分为 7–6(4)、6–3。

这些信息直接排除了“同届真实 R32 Paire–Robredo”解释。无需推断实际比赛时间或参考模型预测。

## 独立全量结构扫描

仅扫描现有 2009–2023 开发目标及同届原始历史，不读取 2024–2025 文件，不训练或评分模型。对每位目标球员，仅检查同届严格更早的淘汰轮次。在全部 36,421 个目标中，“早轮失利却出现在后轮”的来源 ID 唯一为 `2015-316:1`；它会在 Robredo 的 `:20`、`:25`、`:27`、`:28` 四个后轮目标中触发矛盾。

若未排除，该来源也会成为 Paire 的重复首轮历史。它共形成 8 条球员侧历史引用，涉及 7 个唯一后轮目标：

`2015-316:20, :21, :22, :25, :26, :27, :28`。

这证明该特定异常的范围；不能把一种结构检查通过，扩张成“其余所有原始比赛均已逐场官方核实”。已发布库存和 Round 3 的 36,421 行开发目标均不含 `2015-316:1`，真实决赛 `:28` 则保留。既有 `reconcile_matches.py` 已有该异常的排除规则。

继续检查“同一球员同一届有两条相同淘汰轮次”后，又发现三个逐字段相同（仅 `match_num` 不同）的重复组：

| 赛事 | 保留来源 | 排除来源 | 既有处理与本次处理 |
| --- | --- | --- | --- |
| 2021 Rome | `2021-416:14` | `2021-416:25` | 既有 `DUPLICATE_RECORDS` 已排除后者；新历史复用映射 |
| 2021 Stuttgart | `2021-321:5` | `2021-321:13` | 既有 `DUPLICATE_RECORDS` 已排除后者；新历史复用映射 |
| 2022 Gijon | `2022-2807:1` | `2022-2807:5` | 两条均不在原目标；更宽的原始早轮历史只保留前者 |

[2021 Rome 官方主签表](https://www.protennislive.com/posting/2021/416/mds.pdf)在第 19、20 位列出 Nishioka 与 Fucsovics，后者以 6–0、6–2 获胜，仅有一次首轮交手。PDF SHA-256：`ac2cada8dfd46faf9272c4aa6df737a6ebac6a4b20a1f1633552a41068ea4796`。

[2022 Gijon 官方主签表](https://www.protennislive.com/posting/2022/2807/mds.pdf)在第 7、8 位列出 Landaluce 与 Paul，后者以 6–3、6–0 获胜，仅有一次 R32。PDF SHA-256：`dba5200dba9dcbdc23926ce25a16b54af4cdb4ab0d428e196409e3d2ff1ce478`。两条原始记录除 `match_num` 外完全相同，均为 81 分钟。新历史允许更早轮次中的未排名对手，所以必须在该更宽来源上单独消除重复。这里没有将它们新增为目标比赛。

Rome 重复项会影响一个后轮目标；Gijon 重复项会影响两个后轮目标。Stuttgart 重复项虽未在当前目标路径中造成矛盾，也统一复用既有 Tour 去重规则。模块仅对具名映射核对完整字段一致性，不按球员组合或比分通用去重，不删除可能合法的循环赛再交手。若指定重复项缺少保留项或两者字段不再一致，立即报错。

## 允许的局部处理与时间边界

对新增赛事内状态分支采取明确、可审计的规则：

1. `2015-316:1` 不得贡献任何同届早轮历史；保留真实决赛 `2015-316:28`。
2. 复用全部既有 Tour `DUPLICATE_RECORDS` 排除项，并增加官方签表确认的 Gijon 原始历史重复项 `2022-2807:5`。四个排除来源均不在现有开发目标中，实际被中性化的目标数为 **0**。模块对显式传入这些异常来源作为目标的合成输入保留防御性全零回退；这不代表真实目标中存在该行。
3. 不改已有库存、2009–2023 目标、历史 T−21 特征或前几轮产物，不因这一 2015 来源异常改变 2023 的 2,588 场分母。
4. 排除名单及理由进入新模块 metadata，并测试它不能重新进入其他目标的历史。其他来源矛盾仍应报错，不设置通用“忽略矛盾”开关。

赛事内状态本身是**比 T−21 更晚的信息条件**：球员已经完成的同届更早淘汰轮次可以在其后轮开赛前知道。只凭该球员自身晋级路径建立先后关系，不凭统一的赛事开始日期猜逐日顺序，不纳入同轮、未来轮或不相关球员比赛。目标本场胜负、比分和技术统计不得进入它自己的输入；只允许元数据身份核对。没有早轮信息时，模型层应精确回退 R4，而不是另外拟合一个“缺失情形”概率。

修复后全量 36,421 个目标的路径构建通过：不再有早轮失利后继续晋级或同球员同淘汰轮次重复的矛盾；所有排除来源均不进入历史引用；2023 分母仍为 2,588，原目标、标签和既有模型概率没有变化。专用回归测试覆盖三组具名重复、字段不一致/缺少保留项报错、异常来源回退、同轮及未来轮污染和 A/B 对称性。

该来源协调与信息条件升级必须分别报告；本核查不是变更主实验数据口径的授权，也不是改善模型效果的证据。
