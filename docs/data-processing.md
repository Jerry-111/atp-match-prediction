# ATP 男单数据处理与使用说明

第一版建模表已经给出排名差和同场地胜率差，可以直接拟合排名基线。接下来的四组特征实验沿用这批比赛，从比赛总表计算近期综合状态、两位球员的历史交手，再把两列按比赛 ID 接回建模表。两份 CSV 都在仓库中。

| 你的任务 | 使用的文件 | 一行代表什么 |
| --- | --- | --- |
| 拟合排名基线，读取已发布的两项赛前特征和标签 | [基线建模表](../data/processed/model_input.csv) | 一场巡回赛或大满贯正赛。含 16,186 场训练和 2,588 场验证比赛。 |
| 计算另外两项历史特征，查单场比赛和样本覆盖 | [2006–2025 比赛总表](../data/processed/mens_singles_2006_2025.csv) | 一场纳入清单的男单比赛。正赛与资格赛分开计数，共 161,989 场。计算模型特征时取 `source == "tour"`。 |

## 从原始记录到 161,989 场

1. **固定来源。** 主来源为 TennisMyLife 年度文件，巡回赛正赛、挑战赛正赛及巡回赛资格赛各用自己的文件。2006 年另从 Jeff Sackmann 的存档补入四大满贯资格赛和 17 站缺失的挑战赛正赛。读入前核对文件的 SHA-256。另读 2005 年巡回赛文件辅助核验球员身份，2005 年比赛不会计入总表。[主来源](https://stats.tennismylife.org/tennis-match-database) · [2006 年补档和身份核验](../scripts/supplemental_draws_2006.py)
2. **决定哪些比赛回答研究问题。** 纳入硬地、红土和草地的四大满贯、ATP 250/500/大师赛及其历史对应级别的正赛和已收录的资格赛，以及挑战赛各级正赛（含 Challenger 75 和 100）。双方须有不同的球员 ID 和正数排名。比分须非空且不含字母标记；这是按源记录识别完赛的规则。W/O、RET、DEF 分别表示开赛前弃权、赛中退赛和被判负。研究问题因此是「在双方完赛的条件下谁赢」。它无法回答谁更容易受伤。2023 年另做了计入退赛的敏感性检查。[筛选代码](../scripts/baseline.py) · [退赛对基准的影响](../OUTCOMES.md)
3. **核对跨来源记录。** 2006 年补档球员须有唯一的姓名和出生日期证据匹配；日期根据资料内的年龄和赛事日期估算，允许 45 天误差。无法可靠对应的球员不进入合并结果。2010 年 11 站资格赛缺级别和场地，按同届赛事 ID、名称和日期核对正赛元数据，补回 319 场。排名不作均值填补。[补档核查与签表](../DATA.md#coverage-in-the-five-added-seasons)
4. **识别同一场球。** 总表键是 `source:tourney_id:match_num`。同站正赛和资格赛会复用比赛编号。即使编号不同，仍要查同轮次是否重复收录，例如 2007 年萨格勒布整张资格赛签表重复。去除记录前核对签表及对应源行；循环赛再交手、资格赛和正赛再次交手都可以是真实比赛。[逐场校正规则](../scripts/reconcile_matches.py) · [签表核查](../DATA.md#combined-mens-singles-inventory)

| 清单处理步骤 | 行数 |
| --- | ---: |
| 进入审计的源记录（含补档所选签表） | 180,243 |
| 因赛事级别、场地、球员 ID、排名、赛果被排除 | 6,669 + 2,549 + 39 + 2,605 + 6,369 |
| 通过上述筛选 | 162,012 |
| 去除重复记录和一条错录的首轮比赛 | 22 + 1 |
| **最终比赛数** | **161,989** |

每条源记录只归入第一个不满足的筛选条件。最终清单含四大满贯正赛 9,583 场、其余所选巡回赛正赛 39,669 场、挑战赛正赛 86,270 场、巡回赛及大满贯资格赛 26,467 场。[逐年计数](../DATA.md#combined-mens-singles-inventory)

## 模型能看到哪些信息

| 字段或约定 | 用法 |
| --- | --- |
| `player_a_id`、`player_b_id` | 按两个球员 ID 的字符串顺序固定 A、B。用 ID 追踪同一球员，姓名仅供展示；同一 ID 可能有多种姓名拼写。 |
| `rank_a`、`rank_b`、`log_rank_diff` | 排名数字越小越强。排名特征是 `ln(rank_b) − ln(rank_a)`，正值表示 A 排名更高。相同排名时，排名规则弃权；回归的排名差取零。 |
| `surface_rate_diff` | 以赛事日期 T 为基准，只计同一球员在同场地、赛事日期落在 T−364 至 T−21 天（含两端）的已纳入正赛。各自胜率为 `(胜场 + 1) / (场数 + 2)`，再算 A 减 B。没有历史时胜率为 0.5。保留场数和最后一场历史日期便于解释。 |
| `a_won` | 监督学习的目标。1 表示 A 赢，0 表示 B 赢。用此前比赛的标签重建历史，用当前比赛的标签训练或评分。 |
| `match_id`、`season`、`split` | 用来定位比赛和选择样本。建模表使用正赛的 `tourney_id:match_num`；与总表关联时在前面加 `tour:`。 |

**接下来要补的两列。** 从总表选取符合条件的巡回赛和大满贯正赛。对每一场待预测比赛，用赛前固定的 A、B 和该站开赛日 T 计算以下特征。

| 待计算的列 | 取哪些较早比赛 | 如何计算 |
| --- | --- | --- |
| `overall_rate_diff` 近期综合状态 | 每名球员在所有场地、对所有对手的比赛，日期为 T−90 至 T−21 天，含两端 | 各自按 `(胜场 + 1) / (场数 + 2)` 求平滑胜率，然后取 A 减 B。 |
| `h2h_rate_diff` 历史交手 | 只取这两人彼此的比赛，合并所有场地，从 2006 赛季至 T−21 天，含截止日 | 对 A 在双方交手中的胜率使用同样的平滑公式，再算 `2 × A 的平滑胜率 − 1`。查不到交手时取 0，这场比赛仍参与训练或验证。 |

给建模表的 `match_id` 加上 `tour:` 前缀即可与总表一一对应。核对两边球员 ID 后，将新列按比赛 ID 左连接回建模表，检查行数仍为 18,774。[特征口径与完整组合](../DATA.md#what-goes-into-each-comparison)

**按时间验证。** 已发布的同场地特征用 2015 年初始化历史。所有组合共用 2016–2022 年训练比赛和 2023 年验证比赛。排名始终入模，近期综合状态、同场地战绩和历史交手各可加入或略去，共八种预设组合。主比较看排名单独入模与四组全部入模的差距；所有组合均报告准确率和平均 log loss，用 2023 年平均 log loss 最低的组合定型，冻结设置后再评估 2024–2025 年。总表从 2006 年划分 `warmup`，还包含挑战赛和资格赛。选择预测目标时以建模表的 `split` 为准。总表的 19,280 个测试标签留空，建模表只提供开发期的训练和验证行。[已发布特征的计算](../scripts/prepare_data.py) · [已执行的检查](../analysis.ipynb)

**读一场比赛。** 2023 年辛辛那提决赛，A 为排名第 1 的 Alcaraz，B 为第 2 的 Djokovic。按上述窗口，两人的硬地记录分别为 22 胜 / 26 场、27 胜 / 29 场。平滑后 A 为 23/28，B 为 28/31，场地胜率差约为 −8.2 个百分点。这一行可以用来讲清为什么排名和场地战绩有时指向不同球员。[Notebook 中的逐场复算](../analysis.ipynb)

## 哪些结论受数据范围限制

- 排名缺失和未完赛都会改变样本构成。完整记录里的 161,989 场只支持对已纳入比赛的描述。63.37% 是主实验 2023 年验证集的排名基准（1,640 / 2,588），其他赛事层级和赛季有各自的样本和难度。
- 挑战赛资格赛不在覆盖范围内。2006 年 ATP 资格赛只补齐四大满贯；2019 和 2024 年的挑战赛均有可由签表证实的缺站。球员在库内最近 52 周打过几场，与他在所有职业赛场打过几场是两个统计口径。[覆盖缺口和实例](../DATA.md#coverage-of-recent-draws)
- 赛事日期是赛事层面的日期，一场决赛可以与首轮共用同一个日期。源排名通常也没有逐场发布时间。用同届后续对阵、赛果、局分或整届比赛算出的胜率预测早期比赛，会把未来信息带进去。主实验的 21 天滞后会牺牲最近几周的状态，也降低了时间重叠造成的风险。
- 挑战赛和资格赛的部分排名时间有疑点。2024 年诺丁汉草地挑战赛的官方种子表列 Norrie 第 33、Evans 第 62，源记录中 Norrie 在不同轮次出现第 19 和第 39。全库按同一球员、同一届赛事、同一种签表检查，挑战赛有 132 组出现多个排名，资格赛有 98 组，主巡回赛正赛在本版中为 0 组。组内一致仅代表数据自洽。主实验历史只使用所选巡回赛和大满贯正赛。若日后把预测目标扩展到挑战赛或资格赛，需要另行核对赛事日期和赛前周排名，并按签表阶段报告表现。[诺丁汉官方签表](https://www.lta.org.uk/49d1fc/siteassets/events/nottingham/media/nottingham-updated-atp-draw---thursday.pdf)

## 如何确认队友拿到的是同一版

直接下载两份表就可以开始分析。核验命令可在仓库根目录运行。

```bash
python3 -m unittest discover -s tests
```

发布表测试会逐行检查总表 ID、赛季切分和留空的测试标签，再把主实验训练与验证比赛逐场关联回总表，核对双方球员、排名、日期、场地和标签。两份 CSV 的完整 SHA-256 均记录在 [DATA.md](../DATA.md)。若要重建，先运行 `python3 -m scripts.audit_draw_coverage --first-season 2006 --export-inventory`，再运行 `python3 -m scripts.prepare_data`。
